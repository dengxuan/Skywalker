# Skywalker v2.0.0-rc.1 Release Notes Draft

> Status: Draft for `release/2.0` RC tagging  
> Source: `CHANGELOG.md` `[Unreleased]` and `docs/architecture/v2.0-rc-readiness.md`

## Summary

Skywalker v2.0.0-rc.1 is the release-candidate cut for the source-generator rewrite. The release focuses on reducing startup reflection, removing runtime IL emit from DynamicProxy, validating NativeAOT-friendly paths, and consolidating service registration behind `AddSkywalker()`.

## Highlights

- EF Repository registration now uses generated metadata first, with reflection fallback retained only for non-AOT compatibility.
- DynamicProxy now uses source-generated static proxies and no longer depends on Castle.Core at runtime.
- DI auto-registration source generation emits generated registrar metadata consumed by `AddSkywalker()`.
- Source Generator Quality CI covers unit tests, snapshot tests, sample smoke tests, AOT publish, public API checks, and pack validation.
- `Skywalker.Sample.InternalServices` validates internal `[ApplicationService]` DI auto-registration through `AddSkywalker()`.
- `ISettingManager` now supports explicit `(providerName, providerKey)` reads for backend cross-user and cross-tenant management scenarios.
- Messaging and Transport have been spun out to the Vertex project family.

## Breaking Changes

- `Skywalker.Extensions.DynamicProxies` no longer includes Castle.Core runtime fallback. Consumers using `CastleProxyGenerator`, `IProxyGenerator`, or direct Castle APIs must migrate to supported source-generated interface proxy shapes.
- `Skywalker.Messaging.*` and `Skywalker.Transport.*` are no longer part of Skywalker v2.0. Use `Vertex.Messaging` and `Vertex.Transport.*` packages instead.
- AutoMapper is no longer a framework dependency. Applications should use explicit mapping or source-generated mapping such as Mapperly.

## Migration Notes

- Use `AddSkywalker()` as the unified framework entry point, then configure module-specific services such as EF Core through their existing extension methods.
- Add source generator analyzer packages to projects that declare generated service/proxy/repository shapes.
- Fix source-generator diagnostics instead of relying on runtime fallback. Diagnostic docs live under `docs/diagnostics/`.
- See `docs/migration/v1-to-v2.md` for the supported migration path and current limitations.

## Known Limitations

- EF Core repository registration is AOT-friendly on the Skywalker generated-registration path, but full EF Core NativeAOT readiness still depends on EF Core and the selected provider.
- DynamicProxy preview.4 supports interface service proxy shapes only. It does not support class-only proxy replacement, `ref` / `out` / `in` parameters, generic methods, or runtime-only implementation factories.
- DI auto-registration preview.5 does not support open generic implementation registration, runtime-only dynamic service discovery, private nested implementation types, or runtime factory generation.
- EventBus handler source generation, domain event explicit-model refactoring, and stretch source generators are deferred to later v2.x work.
