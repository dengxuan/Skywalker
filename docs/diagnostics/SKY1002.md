# SKY1002: Service type must be assignable from implementation type

| Item | Value |
|---|---|
| Severity | Error |
| Introduced in | 2.0.0-preview.5 |
| Category | Skywalker.Ddd.Abstractions.SourceGenerators |

## Cause

The DI auto-registration source generator found an explicit service type that the implementation type cannot be assigned to. The generator cannot safely emit a service descriptor such as `IService -> Implementation` when `Implementation` does not implement or inherit from `IService`.

This usually happens when a `ServiceType` property on `[Service]`, `[ApplicationService]`, `[Repository]`, or `[EventHandler]` points to the wrong interface or to an interface that was renamed without updating the attribute.

## Incorrect Example

```csharp
using Skywalker.DependencyInjection;

public interface IOrderService
{
}

public interface IInvoiceService
{
}

[ApplicationService(ServiceType = typeof(IInvoiceService))]
public sealed class OrderService : IOrderService
{
}
```

`OrderService` implements `IOrderService`, but the attribute asks the generator to register it as `IInvoiceService`.

## Correct Example

Point `ServiceType` at an implemented interface:

```csharp
using Skywalker.DependencyInjection;

public interface IOrderService
{
}

[ApplicationService(ServiceType = typeof(IOrderService))]
public sealed class OrderService : IOrderService
{
}
```

Or omit `ServiceType` and let the generator use the supported interface fallback:

```csharp
using Skywalker.DependencyInjection;

public interface IOrderService
{
}

[ApplicationService]
public sealed class OrderService : IOrderService
{
}
```

## Fix

1. Check the `ServiceType` value on the DI registration attribute.
2. Make the implementation class implement or inherit from that service type.
3. If the explicit service type is unnecessary, remove `ServiceType` and use interface fallback.
4. Rebuild the project and confirm `SKY1002` is no longer reported.
